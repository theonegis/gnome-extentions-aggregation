# 鼠标如何在屏幕之间移动

## 1. 多块屏幕共享一个逻辑坐标空间

GNOME/Mutter 把显示设置中的屏幕排列表示为矩形 `(x, y, width, height)`。
每个矩形的位置就是屏幕在整个桌面中的位置，x 向右增加，y 向下增加。
例如两块逻辑尺寸为 1920×1080 的屏幕左右排列，左屏范围是
`[0,1920) × [0,1080)`，右屏是 `[1920,3840) × [0,1080)`。
左屏中心 `(960,540)` 跳到右屏中心就是 `(2880,540)`。

逻辑坐标并不总等于显示器物理像素。高 DPI 缩放后，3840×2160 的屏幕在
200% 缩放下可对应 1920×1080 的逻辑区域。扩展使用 Shell 提供的逻辑矩形，
不会再次乘除缩放倍率。旋转、热插拔和排列变化都在每次触发时重新读取。

## 2. 平时用鼠标跨屏

硬件运动经输入栈送到 Mutter；普通鼠标通常提供相对位移，触控板还涉及手势
与加速处理。合成器更新全局光标位置，在屏幕边界按显示排列、指针约束等
规则处理跨屏，向相应窗口发送指针进入、离开和移动事件。
两块显示器只是同一个桌面中的不同区域，并不需要“把鼠标设备切换到另一块屏幕”。

## 3. 本扩展通过快捷键直接定位

1. `Main.wm.addKeybinding()` 注册保存在 GSettings 的四个方向组合。
2. `global.get_pointer()` 取得当前位置，按半开区间找出光标所在的屏幕。
3. `global.display.get_monitor_neighbor_index()` 根据 Mutter 的屏幕邻接规则
   查找该方向的屏幕；返回 -1 时直接结束。
4. 计算目标中心：`x + floor(width/2), y + floor(height/2)`。
5. `global.stage.context.get_backend().get_default_seat().warp_pointer(x, y)` 请求合成器直接移动指针。

这不是模拟“向右移动若干像素”，因此不依赖鼠标速度、加速曲线或当前光标离边缘
有多远。也没有先把鼠标撞到屏幕边缘再反推位置的步骤。
没有主动点击、拖拽、移动窗口或调用激活窗口接口。

## 4. 为什么使用 GNOME 扩展

Wayland 下普通应用不能像传统 X11 应用一样任意读写其他应用的全局指针状态。
GNOME Shell 扩展运行在合成器的 Shell 环境中，可以访问座位（seat，关联键盘、
指针等输入设备）的光标接口。使用这个接口不需要读取 `/dev/input` 或创建 uinput
设备，也不需要额外守护进程。

扩展只在启用期间注册快捷键，禁用时逐个移除；不保留定时器或旧屏幕对象。
快捷键只允许在正常桌面和概览模式下触发，锁屏时不会捕获密码输入。

## 5. 方向规则和限制

原生邻接判定是基于显示器的几何排列，不是屏幕编号，也不是窗口焦点。
目标通常需在移动方向上与当前屏幕相接，并在另一坐标轴上有重叠。
纯对角、间隔或复杂排列是否存在邻居，以 Mutter 的结果为准；本扩展不会另造
一套“最近屏幕”算法，也不越过不存在的邻居绕回。
镜像输出通常对应同一个逻辑屏幕，不能通过光标跳转区分两台物理显示器。
